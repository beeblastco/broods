# Limits

What the Lean library does not say. Read it before relying on a theorem. Add to it whenever a claim is
narrowed.

| Id  | Limit                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L1  | Every theorem is about the Lean model, not the TypeScript or a future port. Replay is the only link between them, and it is a test: passing shows they agree on the vectors tried, never on all inputs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| L2  | A definition can be wrong in a way the kernel accepts. The kernel checks that a proof follows, not that a definition means what its docstring says. A person has to read `Statements.lean`, `Assumptions.lean` and each `Theorems.lean`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| L3  | AI systems wrote this library and these notes, and no person has reviewed the whole of it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| L4  | Forging is treated as impossible, so there are no probability bounds (`Assumptions.lean`, A1).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| L5  | Bun reports line and function coverage but not branch coverage, so a replay-covered line can run without a vector exercising every condition on it. Twin credit uses statement probes instead (L13). Injected faults partly cover that gap.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| L6  | Performance is out of scope. A proof says nothing about latency, memory or cost, so the port still needs its own benchmarks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| L7  | Decision D5: a hook may rewrite tool arguments after policy, so policy theorems cover the model's original call, not the arguments that finally run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| L8  | `Spec.Top.tenantPrivate` treats the worker queue's answer as an account's own input, and has no notion of time. So load on the shared queue (a request refused or delayed because of other tenants) and all timing leak by design, and the theorem does not bound them. No control breaks this theorem, because `World` cannot represent shared state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| L9  | `Spec.Runtime` composes subsystem decisions but models each account's rows as separate, which rests on account-prefixed keys and `assertConversationScope`. It leaves out admin credentials acting on runs, stages, cron and queue time-to-live; subsystem models cover those alone.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| L10 | Most subsystem theorems are local: they state one function's or one step's property, not one over every trace. Only `Spec.Workers` and `Spec.Runtime` hold over every input list. Some names say more than their statement: read `STATEMENTS.txt`, not the name.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| L11 | A twin passes on recorded calls, which are what the repository's tests happen to do. It is evidence the twin matches on those inputs, not on all inputs, and a function's untested branches may be wrong in the model. Recording keeps 100 distinct calls per function. A call past that is not compared, and a statement only such calls reach earns no credit. A call with a value too big to record does not count against a twin's 90% of compared calls when a compared call reached every statement it did, and at least half of all its calls must be compared.                                                                                                                                                                                                                                                                                                                                                 |
| L12 | A twin models a function at the default environment. Calls recorded while a test overrode an environment variable can disagree, and such a twin lists L12 in its gaps and earns no coverage credit while it does. Recorded `Error` values keep `message` and their enumerable fields only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| L13 | Coverage counts executable statements inside functions, by probe where a twin ran and by Bun's line coverage for replay. It does not count module-level constants, or the branch arms replay ran. Branch arms are reported separately and only for twins. An object property holding `undefined` is treated as absent. Parameter defaults are not instrumented. Calls behind a deeper optional chain, such as `a?.b.c()`, are not observed unless `c` is a known built-in, and a function with others earns no traced credit. Generators and iterators are not traced and earn no twin credit.                                                                                                                                                                                                                                                                                                                         |
| L14 | Traced credit means: given these answers from the function's declared boundaries, the twin made the same effects in the same order and ended the same way. It does not prove the boundaries behave as assumed. A label is source text, so a rename needs the twin updated, which is intended. Effects in one overlapping group are compared as a set.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| L15 | Function values are compared by name and symbols by description, so two different functions with one name compare equal. An object property holding `undefined` counts as absent. `$fields`, `$keys` and `$class` are auxiliary and not compared: a twin reading a truncated field can be wrong without detection. Effects are compared by label and arguments, not by the receiver object, so a call on the wrong instance of the same label is not caught. Replay credit is by line coverage of functions a replay file names, not a per-statement comparison.                                                                                                                                                                                                                                                                                                                                                       |
| L16 | The recorder reads `message` on an `Error` even when it is a getter, because callers read it too. It runs no other getter.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| L17 | A twin's view of its arguments and receiver is a snapshot at entry. Code that reads a field again after an `await`, once something else has changed it, sees a value the twin does not, and such a twin must opt out of those calls.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| L18 | Changes to an argument or receiver are attributed by what the call ended with. A leaf belongs to an effect only if its final value is what that effect left, so a write the function makes during an effect, to the same value, counts as the effect's. A callback the caller passed in may touch any argument. A call in which more than 64 effects touch its arguments counts as incomplete. An object reached through an argument and handed to an effect is left out altogether. A write inside a value too large or too deep to record is not seen. A write to an object the call then drops from its receiver leaves no trace, so a twin must opt out of such calls.                                                                                                                                                                                                                                             |
| L19 | Statement credit does not need a precise return value. A twin whose every return is a function or class instance is compared by name or class (L15) and still earns credit for those statements.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| L20 | Nothing runs `formal/` in CI, and recordings are not committed. The coverage number describes the commit it was measured on, and anyone else reproduces it with `conform.ts --all` and `check.ts`. A source change reports as stale only when someone runs those.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| L21 | `Spec.Runtime` and `Spec.Top` end a run the moment its lease is lost, so `oneOwner` and `toolGated` read as if no tool can run after that. The code fences ownership at step boundaries (`harness.ts` `prepareStep`): a stale owner finishes its current step's tools while a new owner may already hold the conversation. `Spec.Runs` models the boundary; the two models are not connected.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| L22 | Some theorems are true by construction and show the model's shape, not a property: `Access.first_match_unique`, `secret_routes_exact`, `Agent.policy_only_refuses`, `finite_run_fuel_decreases`, `finite_run_stops`, `Runs.finished_async_requires_tied_continuation`, `Runs.owner_exclusive`, `Channels.unverified_never_runs` (verification is an input), and `Top.sound` and `Top.tenantIsolation` (credentials are inputs). The `Progress` statements over one fixed schedule are single worked examples. The content is in the `Runs`, `Workers`, `Access.resolve`, `Agent.gate` and `Channels.receivers` models and in the twins. The cron lifecycle's `pause_keeps_run_started`, `settle_first_wins`, `active_envelope_waits` and `answer_settles_own_conversation` follow from the definitions too; `completed_envelope_fails_only_after_limit` and `paused_not_failed_inside_limit` are the two with content. |
| L23 | Sort order in twins is by code point where the code uses `localeCompare`, in webhook candidate order (`sortKey` in `Spec/Channels/Twins/Wavechannels1/Routing.lean`) among others. Recorded ids are lowercase ASCII, so this does not show. Ids that differ in case or punctuation can sort differently.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| L24 | A `Request` or `Response` is compared with its body only when instrumented code built it. One that arrives from a mock or another module is compared by method, URL or status, and headers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| L25 | A closure that runs while its maker is still running belongs to the maker's trace. One that runs after the maker returned gets a trace of its own, `file#maker/label`, and earns credit only through a twin of that name. A maker earns nothing for what its closures do later. Generators and shorthand methods are not traced this way, and their statements earn no credit. A local `function` declaration handed out is not traced either. When a late closure calls a sibling directly, or starts a `new Promise` executor, that code runs under its own trace, so nothing in the caller's trace checks that it ran.                                                                                                                                                                                                                                                                                              |
| L26 | In the cron lifecycle only `deadRunOutcome` is compared against the TypeScript. `settleRun`, `finishRun`, `settleCronRun`, `settleAnsweredRun` and `reschedule` are written from reading the code, because Convex tests load through a loader the recorder does not reach.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| L27 | The channel `authenticate` twins fix which header, secret and fallback each provider uses. They do not specify the signature algorithms or replay windows, which live in the provider SDKs or in effects. A port must take those from the SDK or provider documentation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| L28 | A callback a private method is handed is treated as its caller's own code, so calling it is not an effect. If a caller passes a function from outside the codebase to a private method, that call is not checked.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

| L400 | Sandbox lexical_confinement concerns toWorkspaceRelative's filtered slash components only. It proves no realpath, symlink, mount, shell-command or provider confinement. Lean trimAscii differs from JavaScript trim on non-ASCII whitespace; current directed vectors are ASCII. G6 remains, and G402 identifies a caller that bypasses this check. |
| L401 | Sandbox no_resurrection_without_inflight identifies one physical externalId, not the reusable reservation key. It excludes cached reservation reads, concurrent create/resume, new mirror writes and provider id reuse. The unrestricted claim is false (G401); the abstraction does not model all provider lifecycle paths. |
| L402 | Sandbox cleanup_progress models one expired/orphan reservation with successful active-account lease, CAS take, provider teardown and mirror deletion supplied as explicit inputs. It does not prove that external successes occur, pagination fairness, crash recovery or cleanup for inactive accounts. cleanup_private declares the list of attempted teardown success/failure outcomes; logs and timing are outside that view. |
| L403 | Sandbox tool_attachment proves selection membership only. The account ownership of supplied attachment lists remains the trusted Convex getById(accountId,id) contract under A3; complete resolveAgentRuntime/createTools and approval-gate composition remain open in the manifest. |
| L404 | Reservation key preimages are accountId:agentId:sandboxId, accountId:pinned:trimmedKey, or accountId:workspaceId, then fs- plus the first 40 hex digits of SHA-256(filesystem-namespace followed by NUL followed by the preimage). No hash injectivity or collision-resistance assumption is present in Assumptions.lean, so this subsystem does not claim unconditional disjoint hashed keys for different accounts. |
| L405 | Sandbox manifest coverage is intentionally incomplete: an open row can contain a reviewed and replayed decision kernel while other functions remain unmodelled. Only sandboxProviders.ts currently has whole-file replay status. Machine parser round trips are directed TypeScript tests, not yet a Lean wire-format theorem. |
| L200 | Runs is incomplete: the manifest keeps partially modelled source files open. The atomic ingress abstraction omits scope/account validation, count/byte capacity, `not_running` for late controls, the steer-to-followup mapping, late-result resume retries and stored-result races, application-id persistence/retry, ownerTaskId matching, cursor pagination, retained-row deletion and full payloads. Main claims are local atomic lemmas, not whole-runtime refinement. No fair-scheduling progress theorem or whole-trace lifecycle conservation theorem is established. |
| L201 | Runs conversations_private covers an independently routed product of conversation machines. ownInputs includes all timestamps and scheduling visible to that conversation; the effect view excludes logs, timing, transport errors and global queue pressure. Account/agent authorization and absence of hash collisions are not proved. Cross-session messages deliberately route content to their destination; this theorem does not establish confidentiality between sessions sharing an authorized agent or account. |
| L202 | Runs duplicate_no_second_run assumes the identity row is retained, ordinary admission (not an undelivered late-result resume), and collision-free canonical identities. Today's seven-day status retention permits later re-admission (G200); no perpetual idempotency claim is made. maintenance_records_not_lost concerns the model's retained lifecycle records, not TypeScript retention deletion or crashes before admission commits. |
| L203 | Runs D6 intended contract promotes queued work before TTL filtering after owner loss; while an owner is active, every expiry path must preserve queued work. This includes maintain, prepareAdmissionCoordinator, claimSteering and takeNext, plus recoverQueued's pre-promotion expiry/filter. A successful promotion resets the recovery opportunity for the new lease. The model grants promotion regardless of the old queue deadline; inactive-account disposal and retention policy still need specification. |
| L406 | The trimAscii caveat in L400 describes the initial draft only: Sandbox.jsTrim now lists ECMAScript whitespace and line-terminator code points explicitly. Unicode no-break space, BOM, em space, paragraph separator and non-trimmed zero-width space have directed replay vectors. The lexical-only and caller-completeness restrictions in L400 remain. |
| L500 | Channels capability theorems concern the selected execution agent after same-account rebinding, not the credential holder. Workspaces are original references selected by workspaceId; tool proof abstracts enforcement of the unioned denyTools list. Arbitrary policy semantics, trusted hook effects, role-based authorization and downstream tool construction are not proved by the subset lemmas. |
| L501 | Channels replies_stay_in_conversation means same authenticated provider app and channel, and incoming thread or originating message according to Slack replyIn. source mode may reply at the channel root. Explicit sendChannelReply accepts a trusted persisted source; provider SDK routing, forged source records, caller authorization and multi-recipient outbound tools are outside this theorem. |
| L502 | Channels one-shot progress assumes terminal recording succeeds and the supplied removal outcome succeeds. A failed removal is only attempted/logged, not retried here. Earlier outcome-recording failure may prevent any attempt (G501). D7 fire keys require durable atomic storage under A2; current code still uses random ids (G2). Delivery deduplication is retention-bounded and does not promise lifetime uniqueness after ingress deletion. |
| L503 | Channels schedule_calendar_roundtrip proves numeric calendar-field encoding/decoding after exact-width at(...) syntax, before timezone conversion. String round trips, UTC timestamps, rate and cron translations are directed replay tests; no theorem claims bijective DST conversion, complete IANA data correctness or floating-point overflow safety. |
| L504 | Channels privacy declares unsigned webhook routing response classes, including account/stage/configuration existence, authentication failure, liveness and availability. It excludes timing, logs and denial of service. Media exposes a bare 404 without a valid bearer ticket; ticket holders can observe object existence/size/type/cache expiry and GET bytes. Public cache lifetime and transfer of a ticket are intentional, not a secrecy guarantee. |
| L505 | Channels models decision kernels plus explicit adapter contracts in Contracts.lean. Provider field tables are reviewed source mappings, not proofs of every provider parser. Attachment caching/transcription/storage, credential cache races, all ingress hooks/metadata transforms, complete socket reconnection protocol, complete cron string grammar and every schema rejection are not exhaustively replayed. Manifest notes distinguish these boundaries; this is not whole-file refinement. |
| L506 | Channels private TypeScript functions are replayed by extracting their actual top-level source bodies and injecting imported dependencies; source files are never changed. Signature checks, storage calls, policy/hook outcomes and provider SDKs are symbolic/stubbed. Fault injection for these bodies uses channels-controls.ts with CHANNELS_FAULT, independently of the shared mutation preload. |

| L300 | Agent projection resolves ids globally, including pending approval requests; it permits provider-executed calls without a result. Raw storage may contain unanswered calls after approval/crash, orphan results, duplicates and results out of order. projection_calls_resolved is a membership claim over extracted ids, not a unique ordered call/result pairing theorem. |

| L301 | Agent ancestry requires a present parent principal and existing chain. Missing ancestry remains missing (G301); delegation still preserves account. Cron exclusion concerns normal tool construction and inherited trigger, not trusted hooks or arbitrary external harness implementations. |

| L302 | Agent finite_run_stops is progress of completed-boundary fuel, conditional on at most maxTurn completed steps per slot, at most the supplied number of slots, SDK honoring stop predicates, and external work settling or abort being honored. It does not prove wall-clock termination of hooks, model providers or tools. maxTurn=0 is unlimited and explicitly excluded from a finite step bound. The worker queue is not imported into this independent model. |

| L303 | Agent gating treats the OPA decision and permission-target resolution as inputs. OPA matching is read from broods_authz.rego, but only enforce-deny/default-deny/audit precedence is modelled, not the full selector and condition language. Tool execution relies on SDK honoring approval decisions; D5 permits trusted hook rewrites after judging the original call. |

| L304 | Agent coverage is incomplete. Manifest open rows have explicit remaining obligations; a local model or passing replay does not imply whole-file coverage. Provider recovery currently models one retry per wrapper only. Session projection is not replayed through Session, and raw storage, pruning, compaction persistence, hook scheduling, skills and subagent coordination still require complete modelling. |

| L305 | Agent usage_recording_private covers run-tagged recording and createTaskTotals folding, with no additional leakage; correct tagging and delivery to the recording boundary are inputs, not proved. It excludes timing, logs, resource admission, account-wide aggregation and floating-point/negative/NaN token values. Pricing tokenCostNumerator is an exact natural-number numerator; floating arithmetic is compared only on directed vectors. |

| L700 | Config Value models untrusted finite JSON with integer numbers, unique ordered object keys and no executable prototypes/getters. JS undefined, non-integer/NaN/infinite numbers and duplicate-key parse behaviour are not covered. Recursive merge/sort use fuel 100 and only claim agreement below that depth; strings currently use trimAscii, not full ECMAScript whitespace or UTF-16 ordering. |
| L701 | Config publicHttpsProblem takes the WHATWG URL parser's protocol/hostname result as an explicit input. Replay constructs directed URLs but does not prove the parser, DNS behaviour, DNS rebinding, Unicode host canonicalisation or address routability. Public means outside today's lexical deny list, including its G700 hole. |
| L702 | Config codec_fragment_roundtrip covers only maxTurns and systemPrompt, treating absent/empty system text as the same fragment. It does not prove the complete codec. normalisation_fixed covers an already trimmed canonical baseURL, not idempotence of the complete agent schema. placeholders_intact describes the identity string-validation kernel only; explicit substituteAccountEnvPlaceholders/substituteEnvPlaceholders intentionally resolve secrets and are not yet modelled. |
| L703 | Config envelope model covers blob version/key-id parsing, last-live-key selection, hasKey and needsRewrite. One offline real-crypto test checks round-trip and cross-scope rejection. Cryptographic secrecy, key wrapping/rotation/cache behaviour and all failure paths remain unproved and the manifest row remains open. No envelope plaintext secret-validation predicate exists (G701). |
| L704 | Config is incomplete: open manifest rows retain every unimplemented whole-file obligation. Complete agent schema/evaluation-order errors, provider endpoint validation, codec substitution/extraction, redaction, regex bundle scanning, inputSchema issue rendering, inherited-key remapping, HTTP header behaviour and clientError response conversion still require modelling/replay. Existing safety lemmas are local pure-function statements, not whole-config refinement or trace privacy. |

| L600 | Hosted tenant separation names Lambda warm child keys, per-tenant isolated-vm cache entries, and Dynamic Worker loader keys, not physical hosts. Pooled Node processes intentionally host multiple tenant isolates. Lambda children share the parent UID and are containment rather than an adversarial security boundary. A5 supplies actual sandbox isolation; no V8, OS, cloud-provider or side-channel containment proof is given. Missing account ids collapse to anonymous. |
| L601 | Hosted retry safety concerns the application fallback decision given truthful nothing-ran signals and the six never-connected error codes. A3 trusts cloud providers. G7 is the narrowly separate exception: an isError tool result mentioning a word-boundary 429 or rate limit may cause three more tool calls, even after an effect. SDK-internal AWS retries and cached-discovery reconnects are not proved safe by this theorem and remain open. |
| L602 | Hosted pool progress proves that a scheduled release followed by acquisition succeeds for a live ready worker. It does not prove waiter fairness, no overtaking, startup success, shutdown wakeups, or progress under repeated post-ready death. The source retries startup three times with 100/200ms backoff but can replace post-ready deaths indefinitely. Strong whole-pool progress remains open. |
| L603 | Hosted framing proves invariance under arbitrary partitions of already decoded characters. JSON parsing and escaping execute in replay through Lean Json and the actual JavaScript parser; complete codec inversion and byte-level UTF-8 decoder refinement are not kernel-proved. The frame grammar preserves field order; terminal_encoder_agrees proves every encoded terminal matches the parent prefix, not acceptance of arbitrary reordered or malformed JSON. |
| L604 | Hosted observation privacy is only a projection lemma for an explicit observation boundary. Shared-host identity, listing-cache hit timing and resource contention are declared leaks; authorized own results are observations. It is not a Spec.Private trace theorem over the real runtime and proves no timing isolation, noninterference of host internals, listing-cache races or absence of additional side channels. Strong leakage/refinement remains open. |
| L605 | Hosted settlement is a total list-map theorem for live request ids, with one position per input id. Exact promise settlement additionally requires unique assigned ids, the send/drain promise to settle, honored cancellation, and nonthrowing CPU-meter callbacks; process crashes and a callback throwing before the settlement loop are not covered. Transport failure rejects the batch; missing ids receive a no-response error; duplicate frames overwrite and unknown ids are retained. |
| L606 | Hosted coverage is incomplete. Open manifest rows have local models and replayed decision fragments, not whole-file coverage. Full pool/cache lifecycle, client listing/discovery protocol, all task translator request/auth/continuation paths, complete Convex field validation, isolate execution and egress, and Lambda/Worker loading/budget/error paths remain open. Skill path trim is ASCII in Lean while JavaScript trim is broader. Private function replay extracts actual function bodies with explicit dependency/constant stubs; hosted-controls.ts uses an exact-path preload because the shared preload also matches dependency client.ts files. |

| L100 | Access is incomplete: open manifest rows name remaining functions, even where decision kernels replay. Credential resolution models authenticated signed subjects and trusted storage rows under A1/A3; it does not prove storage lookup correctness, resource authorization after resolution, admin isolation, or downstream tenant composition. Service credentials may choose any account inside the trusted operator boundary; public proxy refusal applies to the service branch, not a colliding configured admin secret. Synchronous success witnesses are provided, not a scheduler progress theorem. |
| L101 | Access first_match_order/deterministic establish one Option Route under ordered predicates: unknown paths such as /unknown return none. A universal claim that every path matches a real router is false. Replay covers canonical URL paths; exact JavaScript regex end-anchor/line-terminator and Unicode case/trim semantics remain outside the current string abstraction. |
| L102 | Access unauthenticated_private covers only a model of pre-authentication gateway observations: selected route, health socket count and maximum, guard HTTP status and request id. Their values leak by design, as do route/method existence, origin/rate/capacity refusal classes and endpoint protocol shape. It excludes timing, logs, response byte lengths, webhook/challenge contents, transport errors and readable claims in signed tickets, and proves no whole-runtime privacy statement. The real gateway health/refusal sample replays; a complete observation extractor for the runtime remains open. |
| L103 | Access principal models project chains onto requester kind/id and delegating agent ids. Optional display names and channel labels are carried by TypeScript but omitted from this model; these metadata are not authorization witnesses. Token purpose is symbolic A1 with explicit wellFormed/authentic inputs: exact parsers, canonical encodings, signed malformed payloads and issuer behavior remain open in the protocol manifest rows. |
