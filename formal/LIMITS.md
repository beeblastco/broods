| L9  | `Spec.Runtime` composes subsystem decisions but models each account's rows as separate, which rests on account-prefixed keys and `assertConversationScope` (`runtimeIngress.ts:1129`). The code checks the agent with a substring test, `includes(":agent:X:")`, where the model uses equality; harmless while core builds every key with its own agent first. Time is not modelled: a lost lease is the `release` input and a timed-out queued message the `expire` input, and `release` ends the run at once where the code's envelope stays `processing` until `maintain` expires it. Agent config is fixed for a theorem, while the code reloads it for every run (`ingress.ts:362`). Left out: admin credentials acting on runs, stages, cron; plan refusals (402, 429); promoting a contiguous group of queued collect/steer messages as one run (`promoteQueuedGroup`, each message is its own run here); steer messages the live owner absorbs at a step boundary (`claimSteering`); late controls answered `not_running`; the worker queue's answer and the subagent persistence mode are inputs. Runs start from a request over the direct API or `/mcp` (whose replay of `POST /v1/runs` carries the caller `mcpAuth` resolved, so an AuthKit sign-in acts as an account key, `DirectRoute.mcp`), a verified delivery, or a spawn; not modelled are late-result resumes (`resumeLostSubagentResults`, `resumeLostAsyncToolResults`) and the turns a persistent child starts in its parent through `message_agents`. Account status is the `status` input. In an inactive account ingress `accept`, `stopOwner` and `recoverQueued` refuse, and every fenced write carrying history rows or an async result runs `requireActiveAccount`. So the account loses its history rows (a `boundary` fails the run), a background run also loses its outcome (its envelope expires, `settledStatus`), and its queue is still handed on, because core settles first and drains with a rowless `takeNext`; the exception is an inline hand-off (channel and queued command turns), whose `takeNext` carries the rows, throws, and leaves the queue unowned (`Handoff`, G202). Replays `inactive-settle-drain` and `inactive-inline-takeNext` drive these mutations on a disabled account. Also refused there but not modelled: session saves, `clearConversation`, `stopOwner`, `writeAsyncAgentResult` (so a non-persistent child's result), `createAsyncAgentResult`, and sandbox reservations, so a tool call that needs a new sandbox fails while the model's `toolCall` picks from the run's sandboxes. On `/mcp` an embeddable key whose user token lists its conversations runs no agent (`mayStart`). Two expiry rules: Runtime's `expire` follows today's code (TTL alone, G1), `Spec.Runs` states the intended D6; a port follows D6. | L18 | Changes to an argument or receiver are attributed by what the call ended with. A leaf belongs to an effect only if its final value is what that effect left, so a write the function makes during an effect, to the same value, counts as the effect's. A callback the caller passed in may touch any argument. A call in which more than 64 effects touch its arguments counts as incomplete. An object reached through an argument and handed to an effect is left out altogether. A write inside a value too large or too deep to record is not seen. A write to an object the call then drops from its receiver leaves no trace, so a twin must opt out of such calls. The same rule covers module state a traced callee leaves behind. A callee answers only until the function's own code runs again (a statement, a resumed `await`, an effect, a callback it handed out), and only until it returns unless its value goes straight to an `await` or `return` of the function itself, or of a closure running as its own trace (L25). What a callee writes after calling back into the function is the function's to state. A parameter default that writes state runs before any probe. A value too large to record is never put on a callee. A write the function makes just before a callee that writes the same field again belongs to that callee, so its twin states it only where the callee leaves the field alone (`GatewaySocket.start` setting `connecting` before `dial`).
