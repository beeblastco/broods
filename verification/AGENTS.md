# verification

Lean 4 models of broods contracts, with machine-checked proofs. Not a Bun workspace. No Mathlib, core Lean only.

- `Broods/Gateway.lean`: the edge route table, `ROUTERS` + `resolveRouter` in `apps/edge/src/routes.ts`, which Traefik serves. proves routing ignores trailing slashes.
- `Broods/Ingress.lean`: `packages/convex/runtimeIngress.ts` envelope lifecycle. proves terminal runs stay terminal, every step moves forward, settle is fenced, `/stop` hits only its generation, `maintain` never expires a run its owner still holds, a step boundary claims steers only behind its own fence and stop check, an ownership proof holds for the rest of its lease, and a queued row completes unrun only through its owner's fenced history write (`insertOwnedEvents`).
- `Broods/AsyncResults.lean`: the async result row, settled with its envelope in one `runtimeIngress.settle`, plus `runtimeAsyncToolResults`. proves envelope and result row agree at every throw point, including a callback throw the harness swallows, a recorded outcome survives later throws, a failed write never loses what the run produced, a tool row settles once, and a late result reaches its parent at most once, by a saved status read or a resume, never through a resume after the row is stored; a status read whose turn dies before its step is saved stores nothing, so a resume tells the parent exactly once (a session that saves no history stores its reads only with its answer), a saved read completes a queued resume of it, a resume whose owner dies before saving it is told again by the next one, and a result is told again after a queued resume of it expired.
- `Broods/Cron.lean`: `packages/convex/agent/crons.ts` run rows. proves the first settle wins and a drained run settles as a no-op.
- `Broods/Sync.lean`: `broods dev` / `deploy` manifest sync with server rename matching. proves the next diff after a sync is deletes only, empty after prune; outright for skill/hook/mcp, given `normalize` round-trips for the rest, and given every stage cron came from code: a prune keeps an agent's or dashboard cron, which the manifest still lists (finding `example`).
- `Broods/SyncExternal.lean`, `SyncCron.lean`, `SyncEnv.lean`, `SyncConcurrency.lean`: stage-scoped external prune by recorded row that waits for the manifest sync, cron keys and orphans, env push, and exclusive manifest PUT claims (overlapping writes are refused with or without a revision; stale cleanup cannot release a newer claim).

- `Broods/DevWatch.lean`, `StageTicket.lean`, `EscFilter.lean`: the CLI's concurrent loops, as step relations over every interleaving, with any number of saves, requests or keys and unbounded time.
  - `DevWatch.lean`: the `broods dev` watch loop in `packages/broods/src/cli/index.ts` `dev()`. proves the stage holds the source whenever no sync is running or queued, unless the last sync failed or a source read errored (both print the error and wait for the next save). The source is the `.ts` and `.md` files the signature hashes. Its first model found two lost saves, now fixed: one made during the first sync, and one undone while a sync ran. assumes every source change reaches the watcher under a `.ts`/`.md` filename: `savedSinceSignature` is set only for those, so renaming a folder twice during a sync can leave a stale stage with no error (not modelled, not reproduced).
  - `StageTicket.lean`: `broods run`'s stage ticket in `run()`. proves no request sends an expired ticket with any interleaving of concurrent re-mints, given skew + latency under the 60 s margin and latency under half the TTL: the server stamps a mint while it is in flight, so an older mint can land last (`ttl_needed` shows latency under the TTL is not enough).
  - `EscFilter.lean`: `stopTurnOnEscape` in `packages/broods/src/cli/tui.ts`. proves a lone Esc read mid-turn only stops the turn (a read of Esc plus more, like Alt+key, is a key and passes through), an arrow key split across reads stays one key, key order holds, and, over infinite behaviors with weak fairness of reads and the hold timer, every held Esc settles and the reads drain once keys stop, given a split key's halves arrive within the 30 ms wait. models a held Esc joining only an arrow's tail; the code joins any read starting with `[` or `O`, so Esc then a typed `[` or `O` within 30 ms is Alt+key and does not stop the turn.

## Rules

- humans read `statements.txt`, not proofs. it pins the printed statement of every theorem; `lake env lean Statements.lean` fails when one changes, so a weakened theorem shows in the diff. an intended change: `STATEMENTS=write lake env lean Statements.lean`, and say why in the PR.
- `mirrors.json` pins a hash of each TypeScript symbol a model mirrors (comments and whitespace ignored). `bun verification/drift.ts` fails when one changed. read the model against the new code, update it if the code changed shape, `lake build`, then `bun verification/drift.ts --write`. a new model lists its symbols there.
- `tests/gateway-oracle.test.ts` runs the executable Lean `route` (`lake build gateway-oracle`) against `resolveRouter` on 5,000 generated requests. a disagreement is a finding: never edit either side to agree.
- `bun run verification:test` runs it with the TypeScript contract tests. those test implementation behavior; only the oracle compares TypeScript with Lean. models omit auth, admission, I/O and many product features.
- the model is hand-written from the TypeScript; the header names the TS, and the docstring on each def names what it mirrors. change the mirrored code = update the model in the same PR.
- every property must be able to fail: keep an `example` that a broken variant (a dropped check, a reordered step) violates it, and one that its hypotheses can hold.
- `example ... := by decide` blocks are findings: concrete inputs where the code does something surprising. fix the code = flip the example to the fixed outcome.
- no `sorry`, no `native_decide`, no new `axiom`, so every proof rests on `propext`, `Quot.sound`, `Classical.choice` only. `lake build` enforces it: the audit at the end of `Broods.lean` fails on any other axiom a `Broods` declaration rests on, `sorryAx` and `native_decide`'s included.
- concurrency and timing go in Lean too: a `Step` relation with one constructor per atomic step in the code, and an inductive invariant over every reachable state. no TLA+.

## Run

- install: `curl -sSfL https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh | sh -s -- -y --default-toolchain none`
- check, in this folder: `lake build && lake build gateway-oracle && lake env lean Statements.lean`, then from the root `bun verification/drift.ts && bun run verification:test`. CI: `.github/workflows/lean-verification.yaml`.
