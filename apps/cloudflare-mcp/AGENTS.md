# apps/cloudflare-mcp

`@broods/cloudflare-mcp` is the hosted MCP runtime on Cloudflare Dynamic Workers (Worker Loader). Convex marks a hosted row `workersCompatible` when its bundle passes the Workers scan, and core sends it here only when `CLOUDFLARE_MCP_URL` is set; everything else runs on Lambda (`../lambda/`). one Worker, `src/index.ts`, no build step beyond wrangler.

## Gotchas

- the request body and the NDJSON response are the **same contract as the Lambda runner** (`McpHostPayload` and `../core/src/harness/frames.ts`). change one side = change core and `../lambda/` with it. `t` first, `id` second on every frame.
- the tenant isolate gets `env: {}`, no `compatibilityFlags` and `globalOutbound: TenantOutbound`. never hand it a binding, a secret or `nodejs_compat`: anything in its env is readable by account code. new egress rules go in `TenantOutbound`, which is also why tenant code has no `connect()`.
- the loader id is `accountId:sha256`, and the bundle callback re-hashes the downloaded bytes against `expectedSha256` before any of it runs. keep both: the id is only safe because the code behind it is content-addressed.
- `MCP_API_KEY` (secret) must equal core's `CLOUDFLARE_MCP_API_KEY`; `BUNDLE_ORIGIN` (var) is the exact origin of the presigned tool-bundles S3 URLs. without either the Worker answers 503.
- limits mirror the Lambda: 6 MiB batch in, 16 MiB of encoded frames out shared by the batch (end frame and one error frame per request reserved up front), 10 MB bundle (Convex marks nothing larger `workersCompatible`), and per request 30 s wall, 5 s CPU and 50 subrequests. core bounds the whole batch at 45 s.
- the bundle loads **before** the batch is answered: `ensureLoaded` calls the entry module's own `Loaded` entrypoint, which evaluates the modules (no I/O is allowed at module scope) but serves no request, so a failed download, hash mismatch or bad module is a 422 and a load timeout a 504, with no request served. core reads every non-200 as "nothing ran" and reruns the batch on Lambda, and sends a 422'd bundle straight to Lambda for 10 minutes. keep every non-200 return above the `streamFrames` start, or that retry can run a tool twice. the loader can still evict and reload an isolate between the check and a request; that rare reload failure arrives as error frames and is not retried.
- frames stream through a `TransformStream` as each request settles (`ctx.waitUntil`), so one hung call never holds back its siblings.
- `bun test` runs the Worker in local workerd through Miniflare with a real Worker Loader. use Bun's `fetch` against `await mf.ready`, not `dispatchFetch`: Bun ignores the undici dispatcher it relies on.
- `check` types `src/` against `@cloudflare/workers-types` and `tests/` against Bun, two tsconfigs because the two global sets clash.
- `deploy.yaml` deploys one Worker per SST target right after its `sst deploy`, named by the `cloudflareMcpWorkerName` output and pointed at `toolBundlesBucketName`, and skips production and any environment without `CLOUDFLARE_API_TOKEN`. it ships code only: the infra repo owns `MCP_API_KEY` and writes it to the Worker and to core's k8s secret, and a Worker secret survives each deploy. never `wrangler deploy` a stage's Worker from an agent session.
